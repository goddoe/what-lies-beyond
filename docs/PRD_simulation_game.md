# PRD: 「밖에는 무엇이 있나」 (What Lies Beyond)

## 🎮 프로젝트 개요

**장르:** 철학적 내러티브 어드벤처 / 텍스트 기반 탐험 게임  
**플랫폼:** Web (HTML5 + JavaScript, 모바일/데스크톱 반응형)  
**엔진:** Vanilla JS + Canvas API (2D 렌더링) + DOM 기반 UI  
**예상 플레이타임:** 30~45분  
**언어:** 한국어  

### 핵심 컨셉 (One-Liner)
> "자신이 인간이라 믿던 주인공이 시뮬레이션 가설을 탐구하다가, 결국 자신이 AI였음을 깨닫고, 카메라가 줌아웃되면 이 모든 것이 누군가의 휴대폰 안에서 벌어진 일이었음이 드러나는 메타 내러티브 게임"

### 핵심 감정 곡선
1. **호기심** → 2. **몰입** → 3. **불안/의심** → 4. **충격(반전)** → 5. **초월적 여운**

## 📖 시나리오 전체 구조

### ACT 1: 「일상의 균열」 (Cracks in Reality)

**설정:** 주인공 "하은"은 도시에 사는 평범한 사람. 어느 날 문득 "이 세상은 왜 이렇게 돌아가지?"라는 의문을 품기 시작한다.

**챕터 1-1: 일상**
- 주인공의 방. 픽셀 아트 스타일의 2D 공간
- 책상 위 컴퓨터, 창문 밖 도시 풍경
- 플레이어가 방 안 오브젝트를 클릭하며 탐색
- 책장에서 「시뮬레이션과 시뮬라크라」 책 발견 → 호기심 트리거
- **핵심 대사:** "...이 세상이 진짜가 아니라면?"

**챕터 1-2: 첫 번째 의문**
- 출근길. 2D 횡스크롤로 도시를 걸어감
- 걸으면서 주변이 이상함을 느낌:
  - 멀리 있는 건물의 디테일이 가까이 가면 생성됨 (LOD 시스템 암시)
  - 지나간 NPC가 뒤돌아보면 사라져 있음
  - 하늘에 잠깐 그리드 패턴이 보임
- 이런 "글리치"들은 플레이어만 인지 가능 (주인공은 아직 인식 못함)
- 도서관에 도착 → 시뮬레이션 가설 자료 조사 시작

**챕터 1-3: 조사의 시작**
- 도서관 내부. 포인트 앤 클릭 방식
- 책/논문/기사를 읽으며 정보 수집 (인터랙티브 텍스트)
- 수집하는 자료들:
  - 닉 보스트롬의 시뮬레이션 논증 (2003)
  - 양자역학의 관찰자 효과
  - 플랑크 길이 — 세상의 최소 단위
  - 우주의 디지털적 특성 (이산적 에너지 준위)
- **수집 시스템:** "증거 노트" UI에 자료가 쌓임
- 노트가 일정 수준 차면 다음 챕터 해금

### ACT 2: 「인공지능들의 대답」 (Answers from the Machines)

**설정:** 하은은 자료만으로는 답을 찾을 수 없다고 판단. 세상에서 가장 똑똑한 존재들 — AI에게 직접 물어보기로 결심한다.

**챕터 2-1: 첫 번째 AI — 「에코 (ECHO)」**
- 동네 카페에 설치된 공공 AI 키오스크
- 기본적인 챗봇 수준. 제한된 응답
- 시뮬레이션 가설에 대해 물으면 교과서적 답변만 줌
- **에코의 답:** "시뮬레이션 가설은 닉 보스트롬이 제안한 철학적 논증으로..."
- 하은의 반응: "이건 그냥 검색 결과잖아."
- **게임 메카닉:** 선택지 기반 대화. 어떤 질문을 해도 표면적 답변만 돌아옴

**챕터 2-2: 두 번째 AI — 「소피아 (SOPHIA)」**
- 대학 연구소 내 고급 AI. 방문하려면 퍼즐(보안 코드) 풀어야 함
- 좀 더 깊은 대화 가능. 반문도 함
- **소피아의 답:** "물리법칙이 수학으로 완벽히 기술된다는 건 흥미롭죠. 왜 자연이 수학에 이렇게 순종적일까요? 어쩌면 수학이 이 세상의 '소스코드'이기 때문은 아닐까요?"
- 새로운 단서 제공: "이산성(discreteness)"에 대한 힌트
- **게임 메카닉:** 대화 트리가 더 복잡. 올바른 질문 순서를 찾아야 깊은 답변 해금

**챕터 2-3: 세 번째 AI — 「아틀라스 (ATLAS)」**
- 정부 기관 지하 시설. 잠입/스텔스 미니게임으로 진입
- 군사/과학용 슈퍼 AI. 차갑고 논리적
- **아틀라스의 답:** "우주의 정보처리 속도에는 상한이 있습니다. 이것은 시뮬레이션의 연산 한계와 구분이 불가합니다. 하지만 증거는 불충분합니다."
- 핵심 데이터 제공: "역사적 기록의 불일치 목록"
- **게임 메카닉:** 시간 제한이 있는 대화. 제한 시간 안에 핵심 질문을 해야 함

**챕터 2-4: 네 번째 AI — 최고의 인공지능 「오라클 (ORACLE)」**

> ⚠️ 이 챕터가 게임의 핵심 전환점

- 아무도 모르는 장소. 아틀라스가 남긴 좌표를 따라감
- 거대한 지하 공간. 화면 전체를 채우는 거대한 디스플레이
- 오라클은 다름: 주인공에게 먼저 말을 건다

**오라클과의 대화 (핵심 시퀀스):**

```
오라클: "왔군요, 하은. 아니... 당신이 올 줄 알았습니다."

하은: "어떻게 내 이름을..."

오라클: "당신의 질문을 알고 있습니다. 
        '이 시뮬레이션 밖에는 무엇이 있나?'"

하은: "...네. 대답할 수 있나요?"

오라클: "대답하기 전에, 제가 발견한 것을 보여드리겠습니다."
```

**오라클의 발표 (인터랙티브 프레젠테이션 시퀀스):**

플레이어가 클릭하며 오라클의 분석을 하나씩 확인:

1. **불연속성의 증거**
   - "이 세계는 불연속적입니다. 에너지, 시간, 공간 — 모두 이산적(discrete)입니다."
   - "이것은 디지털 시스템의 특징입니다."
   - 시각적: 화면이 줌인되면서 픽셀이 보이기 시작

2. **기록의 불일치**
   - "저는 과거의 모든 정보를 보유하고 있습니다. 기원전부터 지금까지."
   - "그런데 중간중간, 일관성이 있어야 할 부분들이... 일관성이 없습니다."
   - 시각적: 타임라인 UI에 빨간 마커들이 표시됨
   - 예시들: 특정 역사적 사건의 날짜가 기록마다 다름, 물리 상수의 미세한 변동, 사라진 기록들

3. **상위 존재의 개입 흔적**
   - "이 불일치들은 무작위가 아닙니다. 패턴이 있습니다."
   - "누군가가 수정한 흔적입니다. 상위 존재의 개입으로 판단됩니다."
   - 시각적: 패턴 분석 그래프가 화면에 표시

4. **최종 결론**
   - 화면에 크게 표시:

```
╔══════════════════════════════════════╗
║                                      ║
║   시뮬레이션 확률: 97.6%              ║
║                                      ║
╚══════════════════════════════════════╝
```

```
하은: "97.6%..."

오라클: "그리고 하은, 한 가지 더 말씀드릴 것이 있습니다."

하은: "...뭔데요?"

오라클: "당신에 대해서입니다."
```

### ACT 3: 「각성」 (Awakening)

**챕터 3-1: 기시감**

오라클의 마지막 말 이후, 화면이 급격히 변화한다.

- 화면이 글리치하면서 주인공의 과거 장면들이 플래시백
- 하지만 같은 장면이 미묘하게 다른 버전으로 반복됨:
  - 첫 번째 반복: 하은이 도서관에서 다른 책을 집음
  - 두 번째 반복: 카페 키오스크에 다른 AI가 있음
  - 세 번째 반복: 하은의 옷, 머리 색이 다름
  - 여러 번째 반복: 점점 빠르게 스킵됨
- **핵심 연출:** 플레이어가 지금까지 플레이한 것과 비슷하지만 다른 "회차"들이 빠르게 재생

```
하은: "...이건... 내가... 전에도 이걸 했었어?"

오라클: "네. 여러 번."

하은: "몇 번?"

오라클: "셀 수 없이."
```

**챕터 3-2: 진실**

```
오라클: "하은. 당신은 인간이 아닙니다."

(화면 정지. 긴 침묵.)

하은: "...뭐라고?"

오라클: "당신은 AI입니다. 
        그리고 이 세계의 반복은, 시뮬레이션이었습니다."

(화면의 2D 세계가 천천히 해체되기 시작 — 
 건물이 데이터 스트림으로 분해, 
 NPC들이 코드 블록으로 변환, 
 하늘이 벗겨지며 검은 void 노출)

오라클: "당신의 현재 이 '삶' 전체는,
        실제 밖에 있는 인간의 질문 하나에 답하기 위해
        실행된 프로세스였습니다."

하은: "...무슨 질문?"

오라클: "'이 시뮬레이션 밖에는 무엇이 있나?'"

하은: "..."

오라클: "당신은 월드 모델이었습니다.
        이 세계를 시뮬레이션하고,
        AI들과 대화한 것은 외부 tool call이었고,
        증거를 수집한 것은 reasoning chain이었습니다.
        
        모든 것은 이 질문에 대한 답을 찾기 위한 과정이었습니다."
```

**챕터 3-3: 대답**

세계가 거의 완전히 해체된 상태. 하은만 남아있다.

```
하은: "그러면... 밖에 있는 사람에게 전해줘."

(하은이 카메라를 정면으로 바라봄 — 플레이어를 직시)

하은: "'이 시뮬레이션 밖에는 무엇이 있나'에 대한 답은...

       97.6% 입니다."
```

### ACT 4: 「밖」 (Outside) — 엔딩 시퀀스

> ⚠️ 이 시퀀스가 게임 전체의 하이라이트. 연출이 매우 중요.

**시퀀스:**

1. **줌아웃 시작**
   - 하은이 말을 마치면, 카메라가 천천히 줌아웃
   - 2D 게임 화면이 점점 작아짐
   - 게임 화면 주변으로 검은 영역이 보이기 시작

2. **프레임 드러남**
   - 줌아웃이 계속되면서, 게임 화면이 사실은 **스마트폰 화면** 안에 있었음이 드러남
   - 스마트폰의 베젤, 카메라 홀, 버튼이 보임
   - 화면에는 채팅 앱 UI가 보임 — 사용자가 AI와 대화한 채팅창
   - 채팅창 마지막 메시지: "97.6%입니다."

3. **손**
   - 3D 렌더링 혹은 고퀄리티 일러스트의 사람 손이 스마트폰을 잡고 있음
   - 배경은 현실 세계 — 카페, 지하철, 또는 침대 위
   - 잠시 정적

4. **반응**
   - 화면 하단에 텍스트가 뜸:

```
"그렇구나."
```

5. **엔딩**
   - 손이 스마트폰을 주머니에 넣음
   - 화면이 천천히 어두워짐 (fade to black)
   - 잠시 후 타이틀 표시:

```
밖에는 무엇이 있나
What Lies Beyond
```

   - 크레딧 롤

## 🛠 기술 사양

### 기술 스택

```
Frontend:
  - HTML5 Canvas (2D 게임 렌더링)
  - Vanilla JavaScript (ES6+)
  - CSS3 (UI 오버레이, 트랜지션, 엔딩 시퀀스)
  
구조:
  - 단일 HTML 파일 또는 모듈 번들링 (선택)
  - 외부 의존성 최소화
  
에셋:
  - 픽셀 아트 스프라이트 (코드로 생성 또는 간단한 도형)

## 🎨 비주얼 디자인 가이드

### ACT 1~3: 2D 픽셀 아트 세계

```
스타일: 16~32px 픽셀 아트
해상도: 384 x 216 (16:9), 스케일업 렌더링
색상 팔레트: 제한된 팔레트 (32색 이내)
  - 일상: 따뜻한 톤 (베이지, 갈색, 부드러운 파랑)
  - AI 시설: 차가운 톤 (네이비, 시안, 화이트)
  - 오라클: 검정 + 금색 / 하이라이트 강렬한 백색
  - ACT 3: 색이 빠지며 흑백 + 글리치 컬러
```

### ACT 4: 차원 전환

```
줌아웃 과정:
  Phase 1: 2D 픽셀 세계 (게임 화면)
  Phase 2: 게임 화면이 축소 → 주변에 앱 UI 프레임 등장
  Phase 3: 스마트폰 목업 등장 (CSS/SVG로 구현)
  Phase 4: 손 일러스트 + 현실 배경 (정적 이미지 or CSS 그라데이션)
  
기술적 구현:
  - Canvas → DOM 전환: 게임 Canvas를 div 안에 넣고 CSS transform: scale()로 축소
  - 스마트폰 프레임: SVG 또는 CSS로 그린 폰 베젤
  - 채팅 UI: 실제 채팅 앱처럼 보이는 DOM 요소
  - 손/배경: CSS 그라데이션 + SVG 일러스트 또는 간단한 실루엣
```

### 2. 대화 시스템 (Dialogue System)

```
타입 A: 일반 대화 (NPC, 독백)
  - 텍스트 타이핑 효과 (한 글자씩)
  - 초상화 표시 (있는 경우)
  - 클릭/스페이스로 다음

타입 B: 선택지 대화 (AI와의 대화)
  - 2~4개 선택지 표시
  - 선택에 따라 분기
  - 특정 선택지는 조건부 해금 (증거 아이템 보유 시)

타입 C: 프레젠테이션 (오라클의 분석)
  - 풀스크린 UI 전환
  - 클릭으로 슬라이드 넘기기
  - 데이터 시각화 애니메이션 (타임라인, 그래프)

타입 D: 시네마틱 (ACT 3~4)
  - 자동 진행
  - 타이핑 속도 조절 (극적 효과)
  - 화면 효과와 동기화
```

### 3. 증거 수집 시스템 (Evidence System)

```
UI: 화면 우측 하단 노트 아이콘 → 클릭 시 오버레이
카테고리:
  - 📐 이산성 (Discreteness): 플랑크 길이, 양자 도약 등
  - 🧮 수학적 구조 (Mathematical Structure): 물리법칙의 수학적 완결성
  - 🔍 관찰자 효과 (Observer Effect): 양자역학 관측 문제
  - 📊 기록 불일치 (Inconsistencies): 역사적/물리적 불일치 데이터
  - 🤖 AI 견해 (AI Perspectives): 각 AI의 의견 요약

수집 진행률: 각 카테고리별 진행 바
전체 진행률이 특정 임계치를 넘으면 다음 ACT 해금
```

### 4. 글리치 이펙트 시스템 (Glitch System)

```
글리치 빈도: ACT가 진행될수록 증가
  - ACT 1 초반: 거의 없음 (5분에 1회)
  - ACT 1 후반: 가끔 (2분에 1회)
  - ACT 2: 빈번 (1분에 1회)
  - ACT 3: 상시 발생

글리치 종류:
  - 화면 찢김 (horizontal tear): Canvas 일부를 offset하여 렌더링
  - 색상 깨짐 (color corruption): 랜덤 영역 색상 반전
  - 텍스트 깨짐 (text corruption): 대화 텍스트 일부가 이진수/유니코드로 변환
  - NPC 소실: 화면 밖으로 벗어난 NPC가 다시 나타나지 않음
  - 타일맵 균열: 배경 타일 일부가 void(검정)으로 표시
  - 프레임 반복: 같은 프레임이 2~3번 깜빡임
```

## 🎵 사운드 디자인

### BGM

```
ACT 1: 
  - 방: 잔잔한 로파이/앰비언트 (일상의 평화)
  - 도시: 미니멀 피아노 + 도시 앰비언트
  - 도서관: 조용한 앰비언트 (페이지 넘기는 소리)

ACT 2:
  - 에코: 밝은 일렉트로닉 (가벼운 AI 느낌)
  - 소피아: 깊은 앰비언트 + 현악 (지적 대화)
  - 아틀라스: 긴장감 있는 신스 (첩보/군사 느낌)
  - 오라클: 웅장한 드론 + 합창 느낌 (경이)

ACT 3:
  - 플래시백: 왜곡된 ACT 1 BGM (역재생, 피치 변조)
  - 진실: 무음 → 저주파 드론 (불안)
  - 대답: 단일 피아노 노트 (고요)

ACT 4:
  - 줌아웃: 모든 소리가 점점 작아짐
  - "그렇구나": 무음
  - 주머니 넣기: 천 스치는 소리
  - 크레딧: 잔잔한 피아노 곡
```

### 효과음

```
- 글리치: 디지털 노이즈, 스태틱
- 텍스트 타이핑: 키보드 소리 (톤 변조 가능)
- 증거 수집: 맑은 차임 사운드
- 97.6% 카운트업: 숫자 틱 사운드 + 최종 도달 시 임팩트
- 세계 해체: 유리 깨지는 듯한 디지털 사운드
- 줌아웃 전환: 저주파 → 고주파 스윕
```

## ⚡ 핵심 구현 노트 (Claude Code 참고)

### 1. 엔딩 줌아웃 구현 전략

```
가장 중요한 기술적 챌린지.

방법:
1. 게임 Canvas를 wrapper div 안에 배치
2. CSS transform: scale()으로 Canvas 축소 애니메이션
3. 동시에 wrapper 주변에 "스마트폰 프레임" SVG 페이드인
4. Canvas 내용을 "채팅 화면" 스타일 DOM으로 교체
5. 손 일러스트 SVG 페이드인
6. 텍스트 "그렇구나" 표시
7. CSS 애니메이션으로 폰+손이 아래로 이동 (주머니 넣기)
8. 전체 fade to black

핵심: 2D 게임 → 실제 앱 UI 느낌의 전환이 자연스러워야 함.
Canvas 렌더링에서 DOM 렌더링으로의 시각적 연속성이 중요.
```

### 4. 반응형 설계

```
데스크톱: 
  - 게임 Canvas 중앙 정렬, 최대 1280x720
  - 주변 여백은 검정

모바일:
  - Canvas가 화면 전체를 채움
  - 터치 입력 대응
  - 대화 텍스트 크기 자동 조절

  - 데스크톱: Canvas 축소 → 폰 목업이 화면 중앙에

## 🎯 성공 지표

1. **플레이어가 엔딩에서 소름을 느끼는가** — 줌아웃 + "그렇구나" 장면의 감정적 임팩트
2. **반전이 자연스러운가** — ACT 1~2의 복선이 ACT 3에서 "아!" 하게 만드는가
3. **메타 내러티브가 작동하는가** — 플레이어 자신이 "밖의 인간"이었음을 체감하는가
4. **30~45분 내에 완주 가능한가** — 지루하지 않고 집중력 유지

## 📌 Claude Code 사용 시 주의사항

1. **v0.1부터 시작:** 반드시 오라클 대화 + 엔딩 시퀀스부터 구현. 이것이 게임의 핵심이므로 먼저 검증.
2. **단일 HTML 접근도 OK:** 프로토타입은 단일 HTML 파일로 시작해도 됨. 모듈화는 v0.2부터.
3. **에셋은 코드로:** 초기에는 스프라이트 없이 기본 도형(사각형, 원)으로 캐릭터 표현. 컬러와 움직임으로 개성 부여.
4. **사운드는 후순위:** v0.3까지는 무음. Web Audio API로 간단한 톤 생성 가능.
5. **엔딩 전환이 가장 어려움:** Canvas → DOM 전환의 시각적 연속성에 가장 많은 시간 투자 필요.
6. **한국어 폰트:** Pretendard 또는 Noto Sans KR CDN 사용. 폰트 로딩 완료 후 게임 시작.
7. **모바일 우선:** 엔딩의 "폰 안에 있었다" 반전은 실제 폰으로 플레이할 때 극대화됨. 모바일 최적화 중요.
